# アーキテクチャ概観：戦闘中の移動・立ち位置・行動の層分担

> このドキュメントについて：設計上の意思決定を、結論だけでなく「なぜそう考えるか」と
> 「検討して捨てた案」まで残す記録です。コードを読まなくても設計の意図と思考の流れが
> 伝わるように書いています。

> 📌 **このドキュメントの位置づけ：** これは単一の決定の記録ではなく、**複数の決定が共有する
> 上位の設計の枠組み**です。戦闘中の移動・立ち位置が*複数の層*に跨ってどう分担・調停されるかを

> いるのは立ち位置を提供する仕組み（ADR-0002・0003・0004）までで、その上に乗る行動ステートマシンや

## 1. 一言で

> 隊形システムは最終的な移動の命令者ではなく、**立ち位置の基準点（ホーム）の提供者**だ。行動
> ステートマシンは**行動の状態**を、単一の**移動の意図の調停役**が複数の移動の意図のうち*実際に
> 実行する一つ*を決める。各システム（隊形・ステートマシン・地形踏破・ボス回避・遠距離の再配置・
> 被弾反応）は直接移動を命じず、**「移動の意図」を提出する**。攻撃・スキル・回避は立ち位置（ホーム）を
> *消さず*、**追従の優先度を一時的に下げるだけ**だ。**優先度（何が大事か）と中断できるか（今止め
> られるか）は分ける。** ボスの全体攻撃のような隊単位の調整は、個々のステートマシンではなく隊・
> イベントの層が立ち位置を割り当てる。
>
> （再掲：このうち実装済みは立ち位置の提供までで、調停役・行動の状態・隊の調整は設計の方針。）

## 2. なぜこの枠組みが必要か

### 2.1. 立ち位置の座標一つだけでは最終的な位置が決まらない

戦闘中の味方の最終的な位置の上には、いくつもの行動が重なる：立ち位置を基準にした再配置、攻撃や
スキルのモーション中の自然な離れ、攻撃後に戻るか交戦を続けるか、立ち位置の周りの横移動、遠距離の
圧の再配置、ボスの全体攻撃の回避、地形踏破中の移動権の固定、被弾・のけぞり・ダウン・蘇生支援の
ような強制された行動。

そこで三つの問いが残る。

1. **立ち位置と行動をどう分けるか？**
2. **複数のシステムが別々の移動目標を求めたとき、最終的な移動命令を誰が決めるか？**
3. **攻撃・回避・地形踏破・復帰の優先度と「中断できるか」をどう扱うか？**

### 2.2. ADR-0001の罠が移動全般で再発する

ADR-0001は地形踏破で既に気づいた ── 複数の主体が直接命令を出すと出どころが散り、「なぜこう動いたか」を
追えなくなる。だから「今その瞬間の*単一の主体*」を立てた。**この概観はその『単一の決定権』の直感を、
ジャンプ限定から*移動全般*へ一般化する。** 隊形・ステートマシン・地形踏破・ボス回避がそれぞれ直接
移動を命じれば、0001が警告したそのグレーゾーン（互いに上書き、「あっちが止めただろう」）が移動全体で
噴き出す。

### 2.3. このプロジェクトの戦闘方針はハイブリッドだ

- **近接**：ある作品のような、ターゲット中心の*張り付く立ち位置*に近い。
- **遠距離**：別の作品のような、*緩い個別の立ち位置*に近い。
- **戦闘行動**：各味方が自分の状態で攻撃・スキル・回避を行う*自律戦闘*。
- **立ち位置**：「正確に立つべき点」ではなく、行動の基準点＝**ホーム**。

一つのモデルへ押し込むと片方が壊れる。だから層に分ける。

## 3. 設計の方針

> ⚠️ この章の大半は**まだ実装していない設計の方針**だ。今あるのは「立ち位置（ホーム）の提供」までで、
> その上に乗る行動の状態と調停役は今後作る。以下は「先に描いた絵」として読んでほしい。

戦闘中の位置の決定を三つの層に分ける。

```text
┌───────────────────────────────────────────────────────────────┐
│ 層1 — ホーム／立ち位置の基準点                                 │
│   「このキャラが基準にする戦闘位置はどこか？」                   │
│   担当：隊形システム、立ち位置の戦略                            │
│   → 今あるもの（ADR-0002・0003・0004）                          │
├───────────────────────────────────────────────────────────────┤
│ 層2 — 戦闘の状態／行動の方針                                    │
│   「今、何をしているか？」                                      │
│   担当：行動ステートマシン                                      │
│   → これから作るもの                                            │
├───────────────────────────────────────────────────────────────┤
│ 層3 — 最終的な移動の決定                                        │
│   「このフレームで実際にどこへ動くか？」                         │
│   担当：移動の意図の調停役                                      │
│   → これから作るもの                                            │
└───────────────────────────────────────────────────────────────┘
```

### 3.1. 最終的な移動は単一の調停役が決める

複数のシステムが同時に移動を命じる構造を**禁じる**。各自が直接命じる代わりに「移動の意図」を
提出し、一つの調停役が優先度・中断できるか・期限・移動の固定を見て最終目標を決める。意図には
種類がある（ホームへ寄る／立ち位置の周りの微移動／遠距離の圧の再配置／攻撃が移動権を持つ／スキルが
持つ／回避／ボス回避／地形踏破／強制イベント／のけぞり、など）。狙いは、複数のシステムが移動を
上書きする状況を防ぎ、各自は「望む意図」だけを出し、最終の実行権は調停役一つが持つこと。
（0001の「単一の主体」を移動全般へ広げる。）

### 3.2. 隊形はホームの提供者だ

隊形はキャラの現在の戦闘の基準点を計算する。立ち位置は「常に正確に立つべき点」ではなく、*やる
ことがない／離れすぎた／戦闘が落ち着いたときに寄っていく基準点*だ。役割ごとに意味が違う ── 近接は
ターゲット中心の張り付く位置、遠距離は射程・安全・視界の基準点、支援はリーダーや隊基準の位置、
スキル時は一時的な上書きの姿勢でホームとは別。

### 3.3. ステートマシンは行動の状態を決める

ステートマシンは今の行動モードを決め、**直接移動を命じない。** 状態に合う「移動の意図」を提出する。
攻撃中はホームの追従を譲り、回避中はホームの追従を止めて安全な位置を優先する、というように。

### 3.4. 立ち位置の解除は「ホームの削除」ではなく「ホームの追従の譲り」だ

攻撃・スキル・回避の最中に立ち位置の座標を*消したり動かしたりしない。* ホームは計算され続け、ただ
今の行動の意図がホームの意図より優先度が高いだけだ。行動が終わって高い意図が消えれば、調停役は
再びホームへ寄る意図を選べる。これは平時の譲り合い、地形踏破中の「進行中は立ち位置の押しを飛ばす」、
そしてADR-0003の固定を一般化したものだ。長期的には「もし攻撃中なら飛ばす」のような例外文を隊形に
積み続けず、**調停役の優先度の選択で統一する。**

### 3.5. 優先度と「中断できるか」は分ける

優先度が高いからといって、常に今の行動を即座に止められるわけではない。

```text
優先度       ：何がより大事か？
中断できるか ：今の行動を実際に止められるか？
```

ボスの即死パターンの回避は最優先だが、キャラが既に空中の地形踏破中だったり、強い攻撃モーションの
キャンセル不可の局面だったりすれば、即座の移動はできないことがある。調停役は両方を見る。優先度の
段階は、上から「強制・生存（ボス回避・即死回避・被弾）」「地形踏破・固定」「スキル・攻撃」「戦術的な
再配置」「ホームへの復帰」。最優先が来ても今の状態が中断不可なら、回避の予約・防御への切り替え・
被弾を受け入れる・次のキャンセル機会で回避、のいずれかで処理する。

### 3.6. ボスの全体攻撃は個々のステートマシン単独で位置を選ばない

複数の味方が同時に回避すべき場面を各自バラバラに解くと、同じ安全地点へ集まり、狭い入口で詰まり、
プレイヤーの移動を妨げ、回避経路が重なる。だから二段階に分ける ── まず隊・イベントの層が危険を
検知して安全地帯の候補を作り、各人へ回避位置を割り当てて意図を出す。次に個々のステートマシンが
今の行動をキャンセルできるか判断し、割り当てられた位置へ意図を出す。隊形はボスのパターンを*知ら
なくてよく*、個々のステートマシンも安全位置の割り当てを単独で解かない。この責任は将来、専用の
調整役が持つ。

### 3.7. 復帰の方針を明示する

攻撃が終わるたびに即ホームへ戻ると「前へ攻撃 → 終了 → 即後退 → また前進」が繰り返されて不自然に
なる。行動ごとに復帰の方針を持つ（即座／手が空いたら／ホームの許容範囲を出たら／行動中に行き先へ
ホーム方向を弱く混ぜる／今の交戦中は戻らない）。ホームへの復帰は**最も低い優先度の意図**だ。他の
攻撃・回避・スキルの意図があれば実行されない。

### 3.8. 微移動は独立した状態ではなく修飾として始める

立ち位置の周りの横移動・微妙な距離調整を、最初から独立した状態にはしない。初めはホームや攻撃準備の
意図の行き先を少し変形する**修飾**として扱う。行動の種類が増え、独立した戦術的価値が出てきたら別の
状態へ格上げする。（早すぎる一般化を避ける ── ADR-0002の案Dと同じ系譜。）

### 3.9. 遠距離の再配置は評価だけで自動的に逃げ続けない — 既に着手済み

遠距離の安全な位置の計算は要るが、「危険なら常により安全な方へ」を評価だけで処理すると無限に逃げ
続ける。だから二段階に分ける ── 「今の位置を捨てるほど悪いか？」（再配置のゲート）と「動くならどこが
良いか？」（位置の評価）。

**このうち再配置のゲートはADR-0003が、位置の評価はADR-0004が、既に具体的に実装している**（この概観の
中で実装まで進んでいる数少ない部分）。ADR-0003のゲート（初回・射程から外れた・猶予つきの脅威回避）が
「いつ動くか」を、ADR-0004の360度の評価が「どこへ」を担う。この概観は、それを意図ごとの重みづけへ
一般化する。

遠距離のAIの基本哲学（ADR-0003と同じ）：**良い場所があるからといって常に動くのではない。今の位置が
悪くなったときだけ動く。危険による移動は許し、最適化のための移動は抑える。**

### 3.10. 立ち位置の周りで小さく流す — 錨は離散、その周りは連続（将来の方針）

> 3.8（微移動は修飾として始める）の**具体的な形**だ。まだ実装前で、どんな形になるかを未来に忘れない
> ために記録する。

**問題意識：** 立ち位置の仕組みは位置を離散的に決める ──「あの場所へ行け」。ところが目標にしている
作品の味方は、立ち位置に着いた後も死んだように立っておらず、敵をうかがって細かく流れる（横移動、
距離の調整）。この「水のように流れる」感じをどう与えるか。

**核心の区別 ── 二つの違う問題を混ぜない：**

```
問題A：味方がどの立ち位置に立つか（配置）       → 離散。立ち位置の層（戦略＋固定）が解く。
問題B：立ち位置に着いた後の細かな挙動（流れ）   → 連続。この3.10が扱う。別の層。
```

この二つを一つの仕組みへ押し込む（例：立ち位置そのものを毎フレーム細かく揺らす）と、ADR-0003の固定と
ぶつかる ── 固定は「行き先を頻繁に変えない」ために作ったのに、流れは「行き先を毎フレーム変えよう」と
するから。そこで**錨（立ち位置）はそのままに、その周りの小さなずれだけを流す。**

```
錨（確定した立ち位置）  ＝ 立ち位置の層が決める。固定で動かない。
小さなずれ（毎フレーム）＝ 錨を基準に、狭い範囲で小さな力場として計算。
最終の行き先          ＝ 錨＋小さなずれ。これを移動システムへ。
```

錨は遠くへ動かないので大きな絵（立ち位置の配置）は保たれ、ずれが毎フレーム小さく揺れるので錨の
周りで流れる。大きな動き（錨まで行く＝今まで通り）と小さな動き（錨の周りの流れ＝この追加）が分かれる。

**なぜ「全体を連続的に流す」ではなく「錨＋小さなずれ」か（捨てた記録）：** 立ち位置の概念自体を捨てて
マップ全体を毎フレーム滑らせる純粋な力場も候補だった（ADR-0004の捨てた案D）。だがそれは「行き先を
決めて向かう」というこのプロジェクト全体の考え方（ADR-0003）と真っ向からぶつかり（行き先という概念
自体がなく流れ続けるモデル）、実装の難度も高い。錨＋小さなずれは、**状態を残し（錨＝どの立ち位置に
属するか）流れも得る（錨の周りの細かな挙動）**折衷で、既存の構造を壊さない。

**移動の意図との関係 ── この3.10は最も低い優先度の「ホームの意図」の一部だ：** 小さなずれは「ホームの
意図の行き先＝錨＋ずれ」として吸収される。攻撃・回避が割り込めばホームの意図が負けるので流れも自動的に
止まり、行動が終わってホームへ戻れば流れも戻る。つまり「攻撃中は流れず、普段は流れる」が例外文なしに
優先度で解ける（3.4の「ホームの追従の譲り」と同じ仕組み）。

**適用範囲：** 近接・遠距離の両方に適用できる ── どちらも確定した立ち位置が錨になるので。近接は
「ターゲットの周りを回る感じ」、遠距離は「敵をうかがう横移動」と挙動が分かれうるが、初めは共通の実装で
始め、分かれたらその時に分ける（早すぎる一般化を避ける）。

**実装の時期：** 行動の層が入った後。それまでは「錨＋小さなずれ」を一時的に立ち位置の後処理として
置くこともできるが、いずれ移動の意図へ吸収される場所なので無理に前倒ししない。

## 4. 決定の過程で得た教訓（未来の自分へ）

- **0001の「単一の主体」の直感が正しく、この概観はその一般化だ。** 「ジャンプの決定権は場面ごとに
  単一の主体」が「移動の命令は単一の調停役」へ広がった。新しいパターンの発明ではなく、確かめられた
  パターンを広げただけ。
- **非対称 ≠ 欠陥（0001の再確認）。** 「戦闘側にまだ行動の層がない」のは*未実装*であって配置の誤り
  ではない。コードの表面の非対称を見て「統合しよう」へ直行するな。
- **意図の種類を最初から多く作ると状態が爆発する。** 一度に多種を作らず、少数（ホーム・攻撃・回避・
  地形踏破）から始めて衝突を表現してみてから増やす。
- **優先度と「中断できるか」を混ぜると行動が硬くなる。** 「大事だ」と「今止められる」は別の軸だ。混ぜると、
  最優先が全モーションを即座に切る大ざっぱなAIになるか、逆に切れない鈍いAIになる。

## 5. 検討して捨てた案

### 案A：隊形の層が行動まで担う

> 隊形システムが立ち位置だけでなく攻撃・回避・スキル・ボスのパターンまで判断する。

**却下。** 立ち位置の計算と戦闘の戦術が混ざり、システムが肥大する。中断の優先度・キャンセルの可否・
攻撃モーションのような*行動の層の知識*が隊形へ侵入する。（0001の「二つの判断を混ぜて見た」罠と同じ。）

### 案B：各システムが直接移動を命じる

> 隊形・ステートマシン・ボス回避・地形踏破が、各自必要なときに直接移動を命じる。

**却下。** 移動命令の出どころが複数になって互いに上書きし、「なぜこの位置へ行ったか」を追えない。0001が
地形踏破で既に拒んだ構造。単一の調停役へ一本化する。

### 案C：攻撃・スキル中に立ち位置の座標そのものを動かす・消す

> 攻撃時に立ち位置をスキルの位置へ動かすか、立ち位置を無効化する。

**却下（ADR-0003と同じ系譜）。** ホームの基準点が消えて行動の終了後の復帰が不安定になる。立ち位置は
計算し続け、高い優先度の意図がホームの意図を上書きする（3.4）。

### 案D：割り込み（ボス回避）を隊形が担う

> ボスの全体攻撃の回避を隊形システムが受けて立ち位置を安全な位置へ再配置する。

**却下。** ボスのパターンは立ち位置の計算ではなく*戦闘行動の割り込み*だ。隊形はボスのパターンを
知らなくてよい（3.6）。ただし安全位置の割り当ては個々のステートマシン単独ではなく隊・イベントの層で
調整する。

### 案E：遠距離のカイティングを評価だけで実装する

> 安全の評価が高い場所へ動き続けさせる。

**却下。** 速い敵・しつこい敵相手に無限に逃げ続ける。再配置のゲートと位置の評価に分ける（3.9）── これは

## 9. 具体ドキュメントとの関係

- **ADR-0001：** 「今その瞬間の単一の主体」（ジャンプの判断）→ この概観の「単一の調停役」へ一般化。
  また判断と物理の分離が、ここでは「層2の行動の決定」と「層3の移動の実行」の分離として再現される。
- **ADR-0002：** 隊形が「ホーム（立ち位置）を提供する」ことは、0002の「戦略が立ち位置を生成する」の上に
  乗る。ホームは立ち位置の*再解釈*（正確に立つ点 → 寄っていく基準点）だ。
- **ADR-0003：** この概観が一般化する**具体の種**だ。0003のキャラごとの固定＝ホームの意図の優先度の
  保持（3.4）、再配置のゲート＝再配置のゲートの最初の実装（3.9）、猶予＝緩やかな切迫度の対（7章）。
  具体（0003）→ 一般（この概観）の順で読むと自然。
- **ADR-0004：** 3.9の**位置の評価**（動くならどこへ）の具体の実装だ。0003がゲート（いつ動くか）を、
  0004がその対の評価を担う。また0004の捨てた案D（連続的な力場）から切り出した「流れる感じ」が、この
  概観の**3.10（立ち位置の周りで小さく流す）**へ続く ── 360度の評価が錨（行き先）を決め、3.10がその錨の
  周りの細かな挙動を扱う。
