# 0005. 敵グループの空間分割 — 疎な格子による近傍検索

## 概要

敵グループの「どれを実際に動かし、どれを生成・休眠させるか」を、毎フレーム全グループを
走査せずに判定するための空間構造を決める。

結論として、**疎な均一格子(Sparse Spatial Hash Grid)** を採用する。木構造(BSP・KD・
octree)による適応的な分割は導入しない。要点は「このプロジェクトのデータ特性に合う、
最も単純な構造」を選んだことであり、この単純さは妥協ではなく適合の結果である。

---

## 問題

敵グループの活性段階(交戦・徘徊・休眠)と生成可否を判定する必要がある。素朴に実装すると、
毎フレーム全グループを巡回してプレイヤーとの距離を測ることになる。これはグループ数に比例
して重くなり、規模が育つほど負担が増す構造になる。

避けたかったのは「保存」そのものではなく、**「毎フレームの全走査」** である。
(保存は避けられない。敵がどこかに配置されているという情報は、必ずどこかに存在する。)

---

## 検討と棄却の理由

### 当初の思い込み — 「空間分割 = 高度なアルゴリズム」

空間分割という言葉から BSP 木のような精巧な構造を思い浮かべ、それを実装すること自体を
目標にしかけた。候補を一つずつ見て、二つのことに気づいた。

各構造が **どんな形をしていて、どのゲーム状況で活きるか** で見ると、選択は明確になる。

#### 均一格子(Uniform Grid)— 採用
世界を同じ大きさの格子で切り、各マスがその中の対象だけを保持する。「プレイヤー周辺の
マス」だけを取り出せば、全体を探さずに近くの敵が得られる。

敵がマップに均等に散らばり、位置がほぼ動かないときに最も速く単純。
→ 静的な配置マーカーの検索はまさにこの状況。**これを採用。**

#### 四分木(Quadtree)
マスを固定サイズで切るのではなく、**対象が多いマスだけをさらに四分割する。**

    何もない荒野    → 大きなマス一つで足りる
    敵100体の都市   → その区画だけ四分割を繰り返して細かく

荒野は空っぽなのに都市に敵が密集するマップなら、都市側だけ細かく割って効率を出す。
→ このプロジェクトのマップにそこまでの密度差はない。小規模では木の巡回コストが利得を上回る。

#### KD木(KD-Tree)
点を軸ごとに交互に半分ずつ割って木にする。**「この地点から最も近い敵1体」** を高速に
見つけるのに特化している。
→ こちらが求めるのは「最も近い1体」ではなく「半径内の全部」。さらに敵が動くと木の更新が
煩雑になる。目的が違う。

#### BVH
対象を囲む境界(箱・球)でまとめ、**そのまとまりをさらにまとめて木に積み上げる。**
剣が敵に当たったか、弾が誰に当たるか — 体積を持つものの衝突・貫通判定に強い。
→ こちらのマーカーは「点」である。境界の木は過剰で、問題は衝突ではなく位置の検索だ。

#### BSP
**空間を平面で二つに割り続ける。** どの壁を先に描くか、壁が視線を遮るか、といった静的な
レベル構造物の処理が本業(Doom/Quake がこれで描画順を解いた)。
→ 敵を探す道具ではない。問題そのものが異なる。

**→ 結論:** 「有名な構造を実装する」ではなく「問題の特性に合う構造を選ぶ」へ目標を立て直した。

### このプロジェクトのデータ特性

- **静的** — マーカーは生成されるまで動かない。
- **均等に配置できる** — 設計者が直接置くので、一マスへの密集を避けられる。
- **小規模** — マップを広げない方針なので、マーカー数が爆発しない。

この三つにより、均一格子の二つの弱点(後述)がいずれも発生しない。だから最も単純な格子が
最もよく適合する。

### 密な格子ではなく疎なハッシュを選ぶ理由

同じ格子でも保持の仕方が二つに分かれる。密な配列はマスがほぼ埋まる世界(タイルマップ等)に
向くが、こちらはマーカーがまばらに置かれるため、空きマスまで配列で抱えると無駄になる。
空きマスはキー自体を持たないハッシュ(疎な格子)が合う。

## 決定 — 疎な空間ハッシュ格子

世界座標をマス座標に変換してマスに入れる。要点は、検索が **巡回ではなく直接アクセス** で
あること。周辺の半径が届くマス座標を直接計算し、そのキーだけを引く。全マスを巡回するのでは
なく、特定座標を引く。ここが「名ばかりの空間分割」と本物を分ける。

### コストをさらに削る二つの工夫

- **移動ゲート:** プレイヤーが一定以上動いていなければ、判定自体を飛ばす。「毎フレーム」を
  「数メートル動くごと」に変える。
- **越境検出の反転:** 「どのグループが半径に入ったか」をグループ側から探さない。プレイヤーの
  近傍マスを引き直せば、越境はその検索の副産物として自然に出てくる。(プレイヤーは一つだけ
  なので、再登録は実質ただ同然。)

### ヒステリシスはマスではなく距離帯に

段階遷移のちらつき防止は、マスの境界ではなく距離帯に持たせる(活性半径 < 非活性半径)。
マス境界に持たせると複雑になる。マスは候補を絞るための器であって、段階判定の基準ではない。

---

## 学んだこと — 空間分割に完全な理論はない

この作業で最大の収穫は、空間分割に抱いていた幻想を捨てたことだ。どの単一構造も、あらゆる
状況を完璧に解く「正解」ではない。

### 弱点1: マスの大きさを誤ると(密度の偏り)

マス一つが覆う範囲を誤ると崩れる。マスが大きすぎると、ボス部屋の入口のように敵が一箇所に
集まる区画で全員が同じマスに入り、結局そのマスの中で再び全員と距離計算することになる —
格子を使った意味が消える。逆にマスが小さすぎると、プレイヤー周辺の広い半径を見るのに無数の
マスを一つずつ探ることになり、周辺マスの巡回がかえって増える。

四分木は混んだマスだけをさらに割ってこれを緩和する。ただしその適応性は「敵が数万体 + 極端な
密度差」で初めて価値を持つ。
→ こちらは設計者が分散して配置することで回避する。**ただしこれは「解決」ではなく「この規模
ゆえに回避できる」だ — 規模が育てば再び向き合う。**

### 弱点2: 動く敵の再計算

敵がマスの境界を越えるたびに、登録し直しが要る。速く動く敵が多いほど、この更新が毎フレーム
積もる。どの構造であれ「動く対象を空間構造へ反映する」問題からは自由になれない — 更新頻度と
正確さのトレードオフが必ず残る。
→ こちらはマーカーが静的なので、再登録は生成時の一度きり。徘徊するグループの低頻度な動きも、
低い更新間隔でのみ位置を更新するためコストが分散する。**これも「回避」であって「解決」では
ない。**

### まとめた認識

- 空間分割は「精巧なほど良い」ではない。分布が均等で静的なら、最も単純な格子が最も速い。
- 木構造の適応性・動的対応はただではない — 巡回コスト、実装の複雑さ、均衡の崩れが代償になる。
  その代償が見合う規模が別にある。
- 完全な単一理論はない。「自分のデータがどんな分布・動的特性を持つか」に合わせて選ぶ、それが
  すべてだ。幻想は「正解の構造がある」という思い込みだった。

## 残された限界 / 今後の方向

#### マーカーが数百を大きく超える、またはマップを広げる場合
マスの大きさの調整(弱点1)が再び論点になる。複雑さの低い順に、マスサイズの再調整 → 階層
ハッシュ格子 → 四分木。**計測でボトルネックが裏づくまで複雑化しない(YAGNI)。**

#### 遭遇の半径が大きく多様になる場合 — 階層ハッシュ格子
グループごとに活動半径が大きく異なると、単一のマスサイズでは両極端の処理が中途半端になる。

    小さなスライムの群れ   半径 300
    大きな野営地          半径 3000
    ワールドボスの領域     半径 10000

小さいマスに合わせるとボス領域が無数のマスにまたがり、大きいマスに合わせるとスライムが一マスに
密集する。階層ハッシュ格子は複数のレベル(例: マスサイズ 500/1000/2000/4000)を持ち、対象の
大きさに合うレベルへ入れて解く。(UE の `THierarchicalHashGrid2D` がこの方式。)
→ 雑魚 / 精鋭野営地 / 遠距離の歩哨 / ボスアリーナが一つのマップに同居したとき、初めて検討する。

#### 動く敵が本格的に入る場合
再登録の頻度が上がる(弱点2)。現状は静的を前提に先送りした問題であり、その時点で更新頻度と
正確さのトレードオフを設計し直す。

## 既存ADRとの関係

- この決定は `UEnemyGroupSubsystem` の活性判定の仕組みを具体化する。
- 空間構造は「生成済みグループの中から近くを探す」ことだけを担う。メモリの読み込み/解放
  (ストリーミング)はこのプロジェクトの範囲外であり、World Partition も用いない — その境界は
  グループ生成方針のADRで扱う。(参考までに、World Partition も大きな単位では実行時グリッドで
  世界を分け、ストリーミング元の周辺マスを読み込み/解放する。こちらが自作するのは、それより
  小さい、実行時のAI候補検索のための格子である。)
