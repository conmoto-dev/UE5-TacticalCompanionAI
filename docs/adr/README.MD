# Architecture Decision Records

> 설계 결정의 "왜"를 남기는 곳. README/메모는 *무엇을/어떻게*를 적지만, 여기는
> **왜 이렇게 갈렸고, 어떤 대안을 왜 기각했는가**를 적는다.
>
> 목적: 프로젝트가 커지면서 과거의 설계 의도를 잊고, 이미 충분히 검토해 끝낸
> 결정을 다시 엎으려는 착각을 막는다. 코드 표면(예: 비대칭한 구조)은 의도를
> 말해주지 않으므로, "비대칭을 보면 합치자"가 아니라 "왜 원래 분리했는지 먼저
> ADR을 읽는다".
>
> 작성 규칙: 압축 금지. 결정은 문장으로 풀어쓴다. 기각한 대안과 이유는 필수.

---

## 형식

각 ADR은 다음을 담는다:

- **결정** (한 줄 요약)
- **맥락** — 왜 이 결정이 필요했나
- **기각한 대안 + 기각 이유** ← 가장 중요. 이게 미래의 재검토를 막는다.
- **결과** — 얻는 것 / 치르는 것 / 남은 숙제
