## (2) "## 열린 질문 (미래 ADR 후보)" — enum/tag 항목을 "닫힘"으로
================================================================

기존:

- **역할 구분자 enum vs GameplayTag** — `ECombatRole` enum인지 GameplayTag인지.
  점프 정책 테이블의 키이자 슬롯 전략 선택의 키. EQ_2.2 BattleFormation_Range에서
  결정 예정. (ADR-0001 §4 ⚠️ 참조)
- **모드 전환 트리거** — 전투 중 점프 결정 주체가 Formation→StateTree로 넘어가는
  전환을 누가/어떻게 트리거하는가. StateTree 설계 본체에서. (ADR-0001 §6 참조)

교체:

- ~~**역할 구분자 enum vs GameplayTag**~~ — **닫힘 (ADR-0002).** GameplayTag 채택.
  직업이 배치 전용이 아니라 타겟팅·스킬·StateTree·GAS까지 걸치는 범용 정체성이라
  계층 태그가 정합. (ADR-0002 §3.3, §5-C, §7 참조)
- **모드 전환 트리거** — 전투 중 점프 결정 주체가 Formation→StateTree로 넘어가는
  전환을 누가/어떻게 트리거하는가. StateTree 설계 본체에서. (ADR-0001 §6 참조)
- **개별형 배치와 헝가리안의 관계** — RangedSafe처럼 멤버별로 위치를 내는 개별형
  에서, 그룹 내 교차 이동 최소화(헝가리안 목적)를 유지할지 포기할지. 1인 계약이
  i→i 대응을 구조적으로 완화하나, 사거리 차가 클 때의 교차 정리는 실측 필요.
  (ADR-0002 §6 참조)
- **여러 직업이 한 배치를 공유** — "Melee와 Tank가 한 부채꼴" 같은 요구가 생기면
  역할↔그룹 1:1 가정과 충돌. 그룹핑 키 재설계 후보. (ADR-0002 §6 참조)
- **집합형/개별형 인터페이스 분리** — 배치 종류가 늘면 단일 계약을
  `ICollectiveSlotGen`/`IPerMemberSlotGen`로 나눌지. 현재는 YAGNI로 보류.
  (ADR-0002 §5-D 참조)
